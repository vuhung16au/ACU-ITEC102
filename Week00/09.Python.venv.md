# Running Projects with Python Virtual Environments (`venv`)

While you *can* install packages globally using `pip3 install`, using a **virtual environment (`venv`)** is always the better choice. 

### Why is `venv` better than direct `pip3 install`?
- **Isolation:** It keeps project dependencies separate. If Project A needs `pandas 1.0` and Project B needs `pandas 2.0`, they won't conflict.
- **Cleanliness:** It prevents your system-wide Python environment from getting bloated with unneeded packages.
- **Reproducibility:** It makes it easy to track and share the exact packages required for your specific project without guessing.

---

## Step 1: Create and Activate the Environment

Instead of installing packages globally, create an isolated environment for your project first.

```bash
# 1. Navigate to the project's source directory
cd ~/00.Work/00.Workspace/ACU-ITEC102/Week06/01.Introduction_and_Series/src

# 2. Create the virtual environment (e.g., named 'week06-env')
python3 -m venv week06-env

# 3. Activate the virtual environment
source week06-env/bin/activate
```
*(On Windows, use `week06-env\Scripts\activate` instead of `source`). You will see `(week06-env)` appear in your terminal prompt when activated.*

## Step 2: Install Dependencies

Now, any package you install goes directly into this isolated environment.

```bash
# Install required packages inside the venv
pip3 install pandas numpy
```

## Step 3: Run the Script (or Notebook)

Once dependencies are installed, you can safely execute your code.

```bash
# Run the Python script
python3 IntroductionandSeries.py
```

> **For Jupyter Notebooks (`.ipynb`):** 
> If you are using VS Code, simply select this new `week06-env` as your Jupyter Kernel. To run via terminal, install jupyter (`pip3 install jupyter`) and run `jupyter notebook` while the environment is active.
