# Python Virtual Environments (`venv`)

A virtual environment is an isolated, self-contained directory tree that contains a Python installation for a particular version of Python, plus a number of additional packages.

---

## Why Use a Virtual Environment?

While you *can* install packages globally using `pip install`, using a **virtual environment (`venv`)** is standard best practice:

- **Isolation:** Keeps project dependencies separate. If Project A needs `pandas 1.0` and Project B needs `pandas 2.0`, they won't conflict.
- **Cleanliness:** Prevents your system-wide Python environment from getting bloated or corrupted with unneeded packages.
- **Reproducibility:** Makes it easy to track, share, and reproduce the exact packages required for your project.

---

## 1. Create a Virtual Environment

Navigate to your project folder in your terminal, then run:

```bash
python3 -m venv .venv
```

This creates a hidden folder named `.venv` containing an isolated Python runtime and `pip` in your project directory.

> **Tip:** While `.venv` is standard convention, you can give it any descriptive name (e.g. `python3 -m venv week06-env`).

---

## 2. Activate the Virtual Environment

Before installing packages or running scripts, activate the environment:

### Windows (Command Prompt / PowerShell)

```cmd
.venv\Scripts\activate
```

*(If using PowerShell and script execution is disabled, you can run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` first).*

### macOS / Linux

```bash
source .venv/bin/activate
```

When active, your terminal prompt will display the environment name in parentheses, such as `(.venv) $`.

---

## 3. Install Packages Inside the Environment

With the environment active, install required packages using `pip`:

```bash
pip install pandas numpy matplotlib
```

Packages are installed exclusively inside `.venv` and will not affect your system Python.

---

## 4. Run Scripts and Notebooks

### Running Python Scripts

With the environment activated, executing `python` (or `python3`) uses the virtual environment's interpreter and installed packages:

```bash
python IntroductionandSeries.py
```

### Running Jupyter Notebooks (`.ipynb`)

- **In VS Code:** Open your notebook, click on the kernel switcher in the top-right corner, and choose your `.venv` environment (or select **"Python: Select Interpreter"**).
- **In Terminal:** With the environment activated, install Jupyter (`pip install jupyter`) and launch `jupyter notebook`.

---

## 5. Selecting the Virtual Environment in VS Code

1. Open your project folder in VS Code.
2. Press `Ctrl+Shift+P` (or `Cmd+Shift+P` on macOS) → type and select **"Python: Select Interpreter"**.
3. Choose the interpreter from `.venv` (e.g., `./.venv/bin/python` or `.\.venv\Scripts\python.exe`).

VS Code will automatically detect and activate this virtual environment whenever you open a new integrated terminal.

---

## 6. Deactivate the Virtual Environment

When you are finished working on your project, exit the virtual environment by running:

```bash
deactivate
```

Your terminal prompt will return to normal.

---

## 7. Best Practices

- **Never commit `.venv` to Git:** Add `.venv/` to your project's `.gitignore` file. Virtual environments should be recreated from configuration files, not shared directly.
- **Record dependencies:** Use `requirements.txt` or `pyproject.toml` so others can reinstall your dependencies (see [04.Python-Libraries.md](./04.Python-Libraries.md)).

---

## Verification

To verify that your virtual environment is properly set up and active:

```bash
# 1. Activate the environment, then check Python path:
which python        # macOS/Linux (should point to .venv/bin/python)
where python        # Windows (should point to .venv\Scripts\python.exe)

# 2. Check Python version:
python --version
# Expected: Python 3.14.x (from the .venv)

# 3. List installed packages in the environment:
pip list
# Should show only the packages installed in this isolated environment
```
