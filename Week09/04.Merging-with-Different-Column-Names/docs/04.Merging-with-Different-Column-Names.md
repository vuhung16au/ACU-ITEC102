# Merging with Different Column Names in Pandas

In real-world data engineering, disparate data sources rarely use uniform column naming schemas.

---

## 1. Mismatched Keys: `left_on` and `right_on`

When tables share an underlying entity identifier under different column labels:

```python
# students has 'student_id', awards has 'applicant_num'
merged = pd.merge(students, awards, left_on='student_id', right_on='applicant_num', how='inner')
```

> **Important**: Pandas will retain **both** `student_id` and `applicant_num` in the resulting DataFrame. To avoid redundancy, drop the superfluous key:
> ```python
> merged = merged.drop(columns=['applicant_num'])
> ```

---

## 2. Overlapping Non-Key Columns: `suffixes`

When both tables contain columns with identical names that are not the merge key (e.g. `rating`, `date`, `status`):
- By default, Pandas appends `_x` and `_y`.
- For maintainability and clarity, always supply descriptive suffixes:
  ```python
  merged = pd.merge(dept_a, dept_b, on='emp_id', suffixes=('_sydney', '_melbourne'))
  ```

---

## 3. Merging on Index: `left_index` and `right_index`

When one or both tables use their index as the primary key:
```python
# left table has key in column 'cust_id', right table indexed by cust_id
merged = pd.merge(orders, customers, left_on='cust_id', right_index=True, how='left')
```
